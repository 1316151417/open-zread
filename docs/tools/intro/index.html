02 / MODELS & PIPELINE

模型是配置，不是绑定。

用 OpenAI 或 Anthropic 协议连接任意兼容服务；目录和正文可以分别选择模型层级。

↔pro + max

三档模型配置

pro 负责目录，max 负责正文；lite 预留给轻量任务。每档都能独立设置 provider、地址、Key、模型 ID 和思考参数。

OpenAIAnthropicDeepSeek自定义地址

README 示例使用 Anthropic 协议；代码默认值是 OpenAI 协议。按服务端实际接口选择，不要只看服务名。

◇两阶段流水线

目录先落盘，正文再并行

阶段 1 把 XML 目录解析成主题列表并写入 wiki.json；阶段 2 为每个主题启动独立 Agent，默认 10 个线程并行生成。

单个主题失败不会终止其他主题；重新运行会创建新版本，不覆盖旧版本。

∥上下文压缩

长对话不会无限增长

消息 JSON 超过 200K 字符时，保留最近 6 条，把更早的对话压缩成摘要。压缩使用当前阶段的模型配置。

按字符数而不是 token 数计算；摘要可能丢失细节，重要约束应写进 Prompt。

$_配置可迁移

settings.json + 环境变量

API Key 支持 ${ENV_VAR} 展开；Anthropic 地址会自动补 /anthropic。配置从当前目录读取， 适合把不同仓库接到不同模型端点。

配置在进程内缓存；修改后重新运行才会生效。

03 / AGENT LOOP

ReAct 循环，
三个只读工具。

「先看目录，再读文件，最后跑一条只读命令。」

每个主题都是一个独立 ReAct Agent：模型发出工具调用，Python 执行工具并把结果写回对话，直到模型不再调用工具。 过程通过事件流暴露，方便观察和调试。

  • get_dir_structure、view_file_in_detail、run_bash
  • 单次默认最多 30 步，超过 200K 字符自动压缩
  • 没有内置写入、删除或执行程序工具
  • 白名单是风险降低，不是操作系统沙箱

05 / EXTENSIONS & BOUNDARIES

可读的实现，明确的边界。

Prompt、协议、目录解析和存储都可以单独阅读和替换；不需要先理解一整套框架。

PROMPTS

本地模板 + Langfuse

默认使用仓库内 Python 模板；启用 Langfuse 后从 Prompt Management 拉取 step1、step2、compress 三个 chat prompt，并可远程迭代。

同步命令：uv run python -m prompt.langfuse_prompt_init

PROVIDERS

双协议适配层

LLMAdaptor 统一消息、工具 Schema 和流式事件，把 OpenAI 与 Anthropic 的差异收在 provider/ 目录里。

支持自定义 base_url；协议兼容性取决于服务端。

PARSING

XML TOC 与 blog 提取

阶段 1 用正则解析 <section> / <group> / <topic>；阶段 2 从输出中提取 <blog> 内容。格式简单，便于观察和替换。

模型不遵守格式时，错误会在解析层暴露。

OBSERVABILITY

可选的 Langfuse

默认关闭；打开后记录流水线阶段、主题 metadata、Agent span 和 Prompt 使用情况。OpenAI 调用自动追踪。

追踪数据可能包含代码片段，使用可信实例。

STORAGE

Wiki 文件格式

wiki.json 描述页面和章节，Markdown 保存正文，current 指向最新版本。没有数据库，也没有隐藏状态。

生成中断会留下部分结果；重新运行创建新版本。

SECURITY

只读边界，不是沙箱

没有 write/edit 工具，run_bash 有白名单和危险模式过滤；但它仍以当前用户权限执行 Shell，可能被绕过。

只在可信仓库运行；需要强隔离时使用容器。

A FEW CLEAR BOUNDARIES

把边界也说清楚。

代码会离开本机吗？

流水线、文件读取和结果存储在本地，但模型请求会携带 Prompt、目录结构和工具读取到的代码片段，发送给你配置的模型服务。 启用 Langfuse 后，追踪数据还会发送到 Langfuse。不要在不允许外部处理的仓库上运行。

生成结果怎么阅读？

Open Zread 输出 Markdown 和 wiki.json，没有内置阅读器。使用 Zread CLI 的 zread browse 预览，或用编辑器打开 .zread/wiki/versions/<timestamp>/。

三个工具真的是只读的吗？

没有 write/edit/delete 工具，run_bash 有命令白名单和危险模式过滤。但它以当前用户权限执行 Shell，白名单对 git、sed、tee、xargs 等命令仍有较大空间，因此不是安全沙箱。只在可信仓库运行。

支持哪些模型？

支持 OpenAI 和 Anthropic 两种协议，可连接 DeepSeek、OpenAI 或任意兼容服务。协议、地址、模型 ID 和思考参数 都在 settings.json 中配置；兼容性最终取决于服务端。

为什么有 lite / pro / max 三档？

当前流水线用 pro 生成目录、max 生成正文；lite 是预留层级，当前版本只加载和打印，不参与主要流程。三档都支持 独立配置，方便后续扩展轻量任务。

和 Zread CLI 是什么关系？

Open Zread 是 Zread CLI 的开源 Python 版本，重点在 Agent 核心实现。CLI 交互、登录、内置模型额度和 Web 阅读器请使用 Zread CLI；本项目生成兼容的 .zread/wiki 文件。
